# Apple Music 风格 UI 改造方案（审查修订版）

本文是 `lx-music-mobile` 的后续实施规格，不代表 UI 已经改完。原六阶段编号保留；本次仅修订方案。

目标是在现有 React Native 应用中统一导航、内容布局、歌曲行、播放器和辅助页面。采用 Apple Music 启发的内容优先布局，但保留本项目的多平台搜索、下载、同步及播放器能力。

## 0. 后续模型如何执行

每轮默认执行一个 Phase；Phase 4、6 可以按文中的子步骤分别执行。用户明确要求连续实施时可以继续，但每个阶段仍须单独验收。不要把本文当成已经验证过的运行结果。

## 1. 参考范围与完成目标

### 1.1 参考范围

本方案是 **Apple Music 风格的 Android 适配方案**，以经典的大标题、内容封面、清晰歌曲行、底部播放控制为参考。

- 首页主标签自 Phase 7 起为四个：**浏览 / 排行榜 / 资料库 / 搜索**。这是本项目的产品选择（排行榜用真实榜单数据充当 Apple Music 的 Radio 位），不是对 Apple Music 官方标签数量、最新布局的完整复刻。Dock 已按用户要求改为浮动玻璃胶囊（见 `docs/apple-music-ui-phase7.md`）。
- 不混用不同系统版本的截图规则。后续若要求对某一 iOS/Android 版本进行像素级复刻，先固定参考截图及版本，再调整本方案；不能直接把这里的全宽 Dock 称为最新官方样式。
- 保留项目名称与图标，不复制 Apple 品牌；沿用项目字体回退，不假定 Android 安装了 SF Pro。
- 当前 `GlassSurface` 是半透明底、高光及叠色组合，不等于原生背景模糊。首版复用现有效果，不能把它验收为原生 Liquid Glass。

功能语义参考：Apple 官方《Play music on iPhone》（固定为 iOS 18 指南地址），包含 Library 分类及 Play/Shuffle 的不同操作。它用于核对功能含义，不证明本方案三标签或全宽 Dock 就是官方原样布局；具体视觉仍以执行前选定的截图为准。

```text
https://support.apple.com/guide/iphone/play-music-iph0138fb328/18.0/ios/18.0
```

### 1.2 目标

1. 首页三个内容标签，与分页器、返回和启动恢复保持一致。
2. 资料库展示封面卡片，浏览以歌单内容为主，音源选择保持清楚且可见。
3. 歌曲行统一排版，但保留排行榜名次、下载进度、队列操作等业务差异。
4. 首页底部组合迷你播放器与标签栏，详情页保留自己的独立迷你播放器。
5. 歌单主视觉、正在播放、设置、菜单和空/错误状态形成统一风格。
6. UI 改动不损失播放、搜索、多选、下载、导入导出、同步等功能。

### 1.3 不在本轮设计目标内

不新增个性化推荐服务、电台、AirPlay、空间音频、假歌手主页或假分类数据；不替换导航框架；不新增主题切换引擎；不重写播放器内核、保活、取链及音源 SDK；不默认引入原生模糊库。

播放详情先保留 RNN push 与已有共享元素过渡。下拉关闭、交互式卡片展开属于单独的后续增强，不能把保留 push 的版本描述成完整复刻 Apple Music 的交互。

以上是审查时的快照。后续执行时重新核实相关符号，不能按行号盲改。

## 3. 信息架构、入口与返回合同

### 3.1 导航与冷启动

保留全部 `nav_*` id。保留 `NAV_MENUS` 所定义的完整 id/type 范围，单独提供主标签数组给 BottomBar、Pager、主标签判断共用；不要删掉设置、下载、排行榜 id 导致类型或旧调用失效。

| id | 名称 | 角色 | 返回/恢复 |
|---|---|---|---|
| `nav_songlist` | 浏览 | Tab 0（默认） | 新安装及无效恢复值的默认页 |
| `nav_top` | 排行榜 | Tab 1 | 独立主标签，保留自己的榜单状态 |
| `nav_love` | 资料库 | Tab 2 | 保留资料库筛选与位置 |
| `nav_search` | 搜索 | Tab 3 | 保留搜索状态 |
| `nav_download` | 下载 | 从资料库进入的覆盖页 | 返回进入前的主 Tab |
| `nav_setting` | 设置 | 从资料库进入的覆盖页 | 先返回设置上级，再返回进入前主 Tab |

唯一主标签顺序：`['nav_songlist', 'nav_top', 'nav_love', 'nav_search']`。

冷启动规则必须确定，禁止保留「也可以」分支：

- 已存储的四个有效主 Tab 原样恢复，不强制把老用户改回资料库。
- 旧 `nav_top` 直接作为排行榜主标签恢复，不再归一为浏览。
- 旧下载/设置值、缺失或未知值统一回到默认标签（浏览），不恢复旧覆盖页。
- 同步 `DEFAULT_SETTING.viewPrevState`、common 初始 `navActiveId/lastNavActiveId`、`dataInit`、主标签判定和 fallback。初始默认值与恢复结果不应造成明显闪页。
- 覆盖页不得写成 `lastNavActiveId` 或覆盖持久化的主 Tab；排行榜是主标签，可以成为返回落点。

### 3.2 返回与页面生命周期

- 排行榜自 Phase 7 起是主标签：不再有「页头返回浏览」语义；Android 系统返回与旋转只保留榜单抽屉的关闭优先级。
- `useBackHandler` 只在页面可见且对应栈层活跃时处理事件。先关闭菜单/弹层/抽屉、退出多选或收起键盘，再执行页面返回；不能让隐藏页面监听器吞掉返回。
- 从排行榜 push 歌单/播放详情后，返回先回排行榜，再回浏览；不因主 Tab 状态变化误退首页。
- 覆盖页打开时关闭底层 Pager 手势，忽略不应生效的 `onPageSelected`；`common.homePageScroll` 配置事件也须遵守此条件。
- 保留页面首次懒加载、可见性、语言/主题更新、滚动位置和搜索内容。排行榜反复进入后榜单选择与列表位置不应无故丢失。
- 防止旋转或重复点击注册多个事件监听器、重复 push 同一详情。返回后焦点落回合理入口。

### 3.3 所有功能必须有明确入口

首版确定为：资料库右上保留导入操作，并提供一个可见的「更多」按钮。更多按钮打开现有首页辅助抽屉；抽屉仅承载下载、设置和受原开关控制的回到桌面/退出等操作。

- 首页取消左侧汉堡气泡与重复的主 Tab 菜单项；保留抽屉的显式按钮入口，不能只剩边缘滑动。
- `common.drawerLayoutPosition`、`common.showBackBtn`、`common.showExitBtn` 在仍使用抽屉时继续生效，退出确认保留。
- 浏览页显示「排行榜」入口，保留标签/排序/打开歌单入口。排行榜自己的榜单选择抽屉、歌单标签抽屉继续使用 `DrawerLayoutFixed`。
- 资料库卡片及其更多菜单保留新建、重命名、排序、去重、导入导出、本地文件导入、同步、删除和歌曲数/刷新状态。空列表也必须能新建或导入。
- 播放更多菜单保留收藏/加入歌单、下载、评论、分享、定位正在播放、桌面歌词、定时退出、音量/倍速/歌词设置及实际已有的音质切换入口。
- 「平台选择」（歌曲来源）与「用户音源脚本管理」不是同一个功能；后者继续从设置访问，不能因移走 SourceSelector 而删除。

### 3.4 首页底部显示规则

| 场景 | 主标签栏 | 迷你播放器 | 列表底部避让 |
|---|---|---|---|
| 四个主 Tab（含排行榜），有当前曲 | 显示 | 显示 | 避让实际 Dock 高度 |
| 四个主 Tab，无当前曲 | 显示 | 不显示 | 仅避让标签栏 |
| 设置/下载覆盖页 | 隐藏 | 隐藏（延续现有规则） | 不叠加首页 Dock 留白 |
| 我的/在线歌单独立详情 | 隐藏 | 使用页面自己的 PlayerBar | 按详情自己的布局，不重复避让首页 Dock |
| 全屏正在播放 | 隐藏 | 隐藏 | 详情自身安全区 |
| 键盘显示且开启 autoHidePlayBar | 原本显示的标签栏保留 | 隐藏 | 根据实际高度更新 |

`hasCurrentTrack` 按播放器的有效曲目信息判断，不等同于 `isPlay`；暂停、缓冲时仍显示当前曲。键盘行为不得以「实现成本高」为理由临时改成另一套合同。

## 4. 视觉、缩放与交互规范

### 4.1 页面轮廓

```text
资料库：大标题/导入/更多 → 已有歌单封面网格 → 组合 Dock
浏览：大标题/排行榜 → 平台筛选与排序标签 → 歌单内容网格 → 组合 Dock
搜索：大标题 → 独占一行的搜索框 → 类型/平台筛选 → 结果或历史 → 组合 Dock
歌单详情：返回栏 → 同一滚动区域内的大封面/标题/动作 → 歌曲行 → 独立迷你播放器
正在播放：关闭入口 → 封面或歌词 → 歌名/歌手 → 进度/播放控制 → 辅助操作
```

不用新建虚假推荐货架掩盖数据缺失。浏览现有数据不足以组成多分区时，使用经过统一排版的真实网格即可。

### 4.2 材质与颜色

- 普通内容背景使用 `c-content-background`，歌曲行保持平面布局；搜索使用 `c-primary-input-background`。
- 玻璃仅用于导航控制区域、抽屉和弹层。设置的内容分组改为实色分组卡片，不能在 Phase 6 仍保留另一套玻璃卡片风格。
- 当前 `c-card-background` 等令牌可能含透明度。若用其代表不透明面板，必须在色板阶段改为合适的实色或明确组合到底色，不能仅因名称含 card 就认为不透明。
- 保留用户已有自定义/动态背景设置；标准验收使用默认背景，开启背景时仍需文字遮罩与可读性。若要删除此能力，须另行确认。
- 初期可复用现有语义色；Phase 6 完成统一浅/深色。`green/black` id 保留兼容，显示名称可以本地化更新。
- 不无条件禁止主题令牌。优先复用；确实需要新语义角色时，说明原因并同步 `src/types/theme.d.ts`、`src/theme/themes/index.ts`、`src/store/theme/state.ts`。即使不新增 key，修改现有角色含义也需检查初始化颜色，避免首帧闪旧色。

### 4.3 尺寸与缩放

下表为项目设计基准，不是物理像素，也不是需要原样照搬的苹果官方尺寸。

| 项 | 基准值/规则 |
|---|---|
| 大标题 | 34 / 700；窄屏或独立页使用紧凑标题，不强挤 |
| 区块标题 | 22 / 700 |
| 歌名 / 歌手 | 17 / 15，主次层级；长文本单行截断、读屏提供完整内容 |
| 脚注 / 时间 | 13；底栏标签 10–12 并验证大字号 |
| 默认歌曲行高 | 60，由同一几何计算提供渲染与定位 |
| 行封面 / 迷你封面 | 40 方形；圆角约 8 |
| 歌单网格 | 竖屏两列，左右内容间距约 16，列间距约 12，封面圆角约 12 |
| 页头封面 | 随可用宽高缩放，不固定挤占小屏全部空间 |
| 点击区域 | 本项目 Android 目标至少 48dp，图标可小于热区；相邻热区不重叠 |

工程约束：

1. `Text size` 已经通过 `setSpText`；`createStyle` 已转换 height/width/padding/gap 等。设计值只转换一次，禁止 `createStyle({ height: scaleSizeH(60) })` 式重复缩放。
2. `onLayout` 得到的实际尺寸不要再交给缩放工具。`StyleSheet.create`、`createStyle`、内联 style 三者的单位必须明确。
3. 复用圆角/边框令牌；不为统一大标题直接全局改 `HEADER_HEIGHT`，它可能同时参与非标题区域尺寸计算。
4. 行高、封面、行距和字号需要一起验证。大字号若超出 60 的布局能力，使用同一行高计算调整所有消费者，不用裁字解决。
5. `LIST_ITEM_HEIGHT` 是共享值，还影响播放队列。修改前搜索全部引用，不把所有列表都硬套成通用歌曲行。
6. 保留现有应用字号与系统缩放支持策略；不在 UI 改造中顺手改 `pixelRatio` 全局算法。若发现缩放既有缺陷，记录并以必要的局部适配解决。

### 4.4 安全区、无障碍与动效

- 顶部状态栏、底部系统导航区分别只计算一次。检查 RNN 是否已避让系统栏，不把现有 Android 12 的固定底 padding 当成所有设备的真实 inset。
- 页面绝对定位的 Dock 用 `BottomInsetContext` 上报实际占用；详情流式排列的 PlayerBar 不应再给列表加同一份空白。
- 测试 Android 手势导航和三键导航、最小支持屏幕、横屏、应用大字号；iOS 只有实际运行过才能标为通过。
- 操作提供本地化的 accessibilityLabel/role/state；选中、播放中、失败状态不只靠颜色区分。
- 动画遵守 `useReduceMotion`。首版保留静态大标题和现有共享元素过渡；可折叠大标题为可选增强，必须复用列表滚动事件，不能新增同方向外层 ScrollView。
- 图标只走现有 Icon 包装；新增别名检查映射、类型与深度导入。不要依赖 SF Symbols 或仅修改字体名制造苹果观感。

## 5. 组件合同与数据行为

优先形成 HomeDock、MusicRow、PlaylistHero 三个共享组件；允许按真实调用关系补充小型辅助组件，不设置「只能新增三个文件」的限制。业务状态留在已有页面/动作层。

### 5.1 HomeDock（Phase 2）

建议位置：`src/screens/Home/components/HomeDock.tsx`。

- 全宽底部容器，迷你条与标签栏间无外部悬浮间隙，材质由父层绘制一次。
- `PlayerBar` 与 `BottomBar` 增加明确的 embedded/无表面模式；不能把现有两块 GlassSurface 再包进第三块造成叠色。单独使用 PlayerBar 时保留自身表面和布局。
- 高度测量随当前曲、键盘、方向、字号及标签可见性更新。隐藏时 inset 及时清零，不残留旧高度。
- 保留暂停/播放、下一首、横屏上一首、曲目信息点击、长按封面定位及原有进度/状态展示入口。
- 迷你封面与歌名打开播放页时，核对当前可见 RNN componentId；从 MylistDetail/SonglistDetail 进入不能错误地 push 到被遮挡的 home 层。
- 保留共享元素 nativeID，检查活跃页面中重复 id 和无封面回退；无曲目时不允许进入空播放页。

### 5.2 MusicRow（Phase 3）

建议位置：`src/components/common/MusicRow.tsx`。组件接收展示数据，不订阅整个播放器状态，也不自行取封面。

必要信息：title、subtitle、coverUrl、可选时长、active、selected、disabled/状态信息、可选 rank 或元数据、宽度/统一行高、onPress、onLongPress、onPressMore。

- 在线和我的列表保留薄适配层，负责原音乐对象、索引、选择模型、菜单参数。不要把 online/local/download 类型强转成同一种数据。
- `onPressMore` 必须继续提供菜单锚点 `{ x, y, w, h }`（现有测量合同），并保留点击对象/索引；菜单不能因为抽组件而定位到左上角。
- active 表示当前曲；播放/暂停区分可由可选状态提供，不能对暂停曲错误显示“正在播放”。选中与当前曲是独立状态。
- 混合平台搜索及混合来源歌单不能一律隐藏来源。遵守现有 `showSource` 语义，用次要文字/紧凑标识保留区分；单来源页可省略重复标记。
- 音质提示若从行内收起，必须有真实可达的详情/菜单展示处；未迁移前保留现有提示，不杜撰设置开关。
- 排行榜保留名次；播放队列保留排序/移除；下载保留进度、错误、重试等专用控件。可以复用排版，不强制所有列表使用同一个行组件。
- 空 URL、加载失败、本地文件、较慢网络均使用固定尺寸占位，不触发逐行额外请求，不阻塞点击和滚动。
- memo/比较函数应覆盖实际依赖的标题、封面、选择、播放状态及 handler；避免曲目原地更新后不刷新，也避免播放进度每秒带动全列表刷新。

### 5.3 PlaylistHero（Phase 4）

建议位置：`src/components/common/PlaylistHero.tsx`。

- 接收封面/占位、标题、可选创建者/描述/歌曲数、加载/失败状态和 onPlay/onShuffle/onCollect/onMore；不直接访问特定 store。
- 作为歌曲 FlatList 的 ListHeaderComponent 与列表一起滚动；紧凑返回栏留在外面。不要固定一大块封面压缩小屏列表，也不要在 ScrollView 中再嵌同方向 FlatList。
- 我的详情入口为 `src/screens/MylistDetail/index.tsx`；在线详情为 `src/screens/SonglistDetail/index.tsx`。两条实际路径都要接入。
- Hero 加入后修正列表定位偏移：header 高度、分隔线、内容 padding、列数全部纳入 getItemLayout/scrollToIndex；可变高度用真实测量，不能硬猜。

### 5.4 播放与随机按钮必须有真实行为

原方案中「随机暂时绑定普通播放」的条款取消。

- 播放按钮沿用现有播放全部动作及当前模式，保持兼容；页面展示当前随机状态。若以后要求该按钮强制顺序播放，应作为明确行为变更处理。
- 随机按钮在数据就绪后，通过现有 `updateSetting({ 'player.togglePlayMethod': 'random' })` 和播放动作接入真实随机模式；首次播放位置也要随机选择，不能只换图标或只随机第一首后继续顺序播。
- 我的歌单使用真实列表 id；在线歌单使用现有临时列表与来源标识。首版在线随机先通过现有完整歌单获取能力准备可用列表，成功后再切换模式并播放，避免只对第一页随机却声称全歌单随机。
- 当前在线 `SonglistDetail/listAction.ts` 普通播放有先播已加载列表、再补全的逻辑，保持该动作行为；随机可在页面动作层增加包装，复用现有 API，不能重写内核。
- 重复点击期间显示 busy/禁止重复操作；异步结束核对目标歌单和请求身份，已切到另一歌单/取消时不抢播。
- 无内容、加载失败时不切模式、不清空当前队列。播放尝试失败时按现有错误处理反馈，不伪装成成功；随机模式的持久化与现有模式按钮保持一致。
- 不原地洗牌用户歌单，不改变同步顺序。若现有公开接口无法实现，记录阻塞并完成必要的最小适配；禁止交付假随机按钮。

## 8. 验证方法与覆盖矩阵

### 8.1 可执行检查

- 先确认仓库现有工具可用。优先用已有 ESLint 对改动的 JS/TS 文件进行定向检查；本次 `package.json` 有 `lint`，没有 `test` 或 `typecheck` 脚本，不得编造已跑 `npm test`。
- TypeScript 需要时调用已有编译器做 noEmit 检查，先记录基线问题，区分本次新增错误；不临时安装测试框架。
- 导航恢复、列表定位、随机动作等行为可用现有测试能力做针对性回归；纯圆角/文案不为覆盖率写无意义测试。
- 原生 bundle/构建仅使用现有依赖和环境。用户没有要求时不启服务常驻、不装大型工具链；无法运行则记录准确命令/阻塞，不能写成通过。

### 8.2 必查场景

| 类别 | 场景 |
|---|---|
| 恢复 | 三个有效 Tab、旧 nav_top、旧设置/下载值、无效/缺失值 |

| 播放 | 无曲目、暂停/缓冲/失败、歌词/无歌词、队列、倍速/音量、通知栏与后台切歌回归 |

| 主题 | 浅/深、跟随系统、启动首帧、动态/自定义背景、选中/禁用/危险状态 |
| 语言与可访问性 | 简中/繁中/英文、长文本、读屏标签/焦点/选中状态、减少动态效果 |

不要求每次微调跑完整矩阵：阶段内跑其直接影响项，全局完成前覆盖整张表。
